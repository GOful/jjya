# Supabase 공유 DB 설정

현재 연결 주소와 Publishable key는 설정되어 있습니다. DB 준비가 끝나기 전에는
`supabase-config.js`의 `enabled: false`로 기존 개인 저장 방식을 유지합니다.
공개 키는 브라우저에 노출되는 용도이며 비밀번호나 secret/service_role 키를 넣으면 안 됩니다.

## 프로젝트에서 한 번 실행

1. Supabase 프로젝트의 **SQL Editor → New query**에서 [setup.sql](setup.sql)의 전체 내용을 붙여넣고 **Run**을 누릅니다.
   `app_catalog`, `work_logs`, `copy_events` 테이블과 RPC, 권한 정책, 기존 점검 데이터가 생성됩니다.
   재실행해도 기존 항목이나 사용 기록은 초기화되지 않습니다.
2. **Authentication → Sign In / Providers → Anonymous Sign-Ins**를 활성화하고 저장합니다.
   화면 이름이 다르면 Authentication 설정에서 Anonymous를 찾습니다.
   사용자에게는 이메일/비밀번호 화면이 표시되지 않습니다. 브라우저가 자동으로 익명 세션을 만듭니다.
3. `supabase-config.js`의 `enabled`를 `true`로 바꾸고 GitHub `main`에 반영합니다.
   작업을 맡긴 경우 “SQL 실행했고 익명 로그인 켰어”라고 알려주면 연결 활성화를 이어서 진행할 수 있습니다.
4. GitHub Pages 배포 완료 후 사이트를 새로고침합니다. 상단에 **공유 저장 모드**가 표시됩니다.

설정 파일의 URL과 키는 현재 프로젝트의 공개 연결 정보입니다.
프로젝트 재생성 시 Project URL과 Publishable key(또는 anon public key)를 갱신합니다.

## 공유 방식

- 사이트 주소를 아는 누구나 같은 일지·점검 내용·사용 횟수를 읽고 수정할 수 있습니다.
- 별도의 사용자 가입이나 이메일 입력은 없습니다. DB는 익명 세션이 있는 요청만 받습니다.
- 한 팀용 공유 공간입니다. 팀을 분리하거나 개인별 접근을 제한하는 기능은 없습니다.
- 기존 브라우저의 로컬 사용 횟수는 DB에 자동 합산하지 않습니다. 새 DB의 횟수는 0에서 시작하며 기존 로컬 기록은 남겨둡니다.
- **저장**은 일지 본문·선택 항목·기간을 공유 DB에 저장하며 사용 횟수를 증가시키지 않습니다.
- **복사**는 클립보드 복사와 공유 저장을 수행하고, 해당 일지에서 처음 복사하는 항목만 1회 집계합니다.
- 같은 일지를 다른 PC에서 다시 복사해도 중복 집계하지 않습니다. **새 일지** 또는 다른 위험예지훈련 선택으로 새 일지를 만듭니다.
- 페이지에 들어오면 최근 저장된 일지를 불러옵니다. 최근 30개 일지는 상단 목록에서 선택해 **불러오기** 할 수 있습니다.
- 횟수는 접속·저장·복사·불러오기 때 갱신됩니다. 다른 사용자의 변경은 **공유 횟수 새로고침**으로 확인할 수 있습니다. 실시간 자동 동기화는 아닙니다.
- 다른 사람이 같은 일지를 먼저 저장한 경우 덮어쓰기를 거부합니다. 현재 본문을 따로 복사해 둔 뒤 다시 불러옵니다.
- **점검 내용 편집**으로 기존 항목을 수정할 수 있습니다. 항목 ID/위치를 유지해 과거 횟수와의 연결을 보존합니다. 수정 내용은 새로고침하면 적용됩니다.
- 서버 저장이 실패하면 현재 본문을 유지하고 실패를 표시합니다. 로컬 저장으로 몰래 대체하지 않습니다.

공유 정보는 Supabase에 저장됩니다. GitHub 저장소에는 일지나 세션 토큰을 저장하지 않습니다.
로그인 없는 공개 편집 방식이므로 민감한 개인정보를 일지에 넣지 마세요.

## 검증

```sh
npm ci
npm test
```

PGlite(PostgreSQL WASM)에서 SQL을 실행해 익명/인증 요청 권한, 저장/복사 분리,
중복 집계 방지, 여러 사용자 공유, 버전 충돌, 오류 시 트랜잭션 롤백을 검증합니다.
Node WASM 실행이 제한된 샌드박스에서는 제한 해제 후 실행하고, 출력에 실제
`shared database: ...` 하위 테스트가 실행됐는지 확인합니다.

브라우저 통합 검증(Playwright Python 및 Chromium 필요):

```sh
python tests/browser_shared.py
```

이 테스트는 서로 다른 두 브라우저와 **모의 Supabase HTTP API**를 사용합니다.
실제 프로젝트의 Auth 설정이나 네트워크 상태를 검증하는 테스트는 아닙니다.
실제 연결 검증은 위 설정 후 서로 다른 두 브라우저에서 저장·불러오기·복사를 해보아야 합니다.
